# 诊断协议（Diagnostic Protocol）

新建课程、设计练习、安排检查点、评估备考起点、或判断是否升级难度时读这里。课程侧应用见 learning-course 的 `references/state.md`；考试侧应用见 exam-prep 的 workflows Diagnose 分支。

## 何时诊断

只有起点不确定且答案会改变路线时才诊断。路线已明确时不诊断；题数和形式以获取"足以选择起点"的证据为限。

## 停止条件

诊断的目的不是打分，而是发现关键前置缺口、误解或任务负荷。拿到足以选择起点的证据即停，不做全面摸底。

## 记录什么

原始回答逐字保留；提示使用和证据强度如实记录。一次猜对或主观自评不能判定掌握。

## 失败类型

把错误归类后再调整教学：

| 类型 | 表现 | 干预 |
|---|---|---|
| 知识缺口 | 缺少术语、规则或前置事实 | 补前置知识 |
| 表征困难 | 看不出问题与模型的对应关系 | 换表征 |
| 步骤负荷 | 理解局部，但工作记忆保持不了完整流程 | 拆步骤 |
| 条件误判 | 知道规则，但不知道何时适用 | 增加辨析 |
| 迁移失败 | 示例中会做，换情境就不会 | 加入变式 |
| 反馈不足 | 行为证据不足，无法确认原因 | 先做更小的诊断任务 |

## 证据足够条件

诊断证据足够 = 能回答"下一步从哪里开始、用什么干预"。尚不能区分下一步路线时继续收窄；已经能区分时立即停止。
