# Exam Workflows

Read only the branch matching the active mode. Every branch ends when its listed artifacts and state are both current.

## Diagnose

1. Register available scope, sources, exam date, target, and time budget; mark unknowns explicitly.
2. Select a minimal source-backed sample that can change the training plan, then capture attempts as finalized records.
3. Summarize observable gaps, timing risk, and evidence limits; update only measured readiness metrics.

Completion criterion: `PLAN.md` names the starting priorities, diagnostic records support the readiness baseline, and unknown scope remains `provisional`.

## Plan

1. Reconcile `SOURCES.md`, question bank, error log, remaining time, and target.
2. Rank topics by exam value, current evidence, and error cost; assign drills, reviews, mocks, and cram checkpoints.
3. Sync materials and write the next concrete session into `PLAN.md`.

Completion criterion: every scheduled block has a source or diagnosed weakness, a time box, and a checkable output; `confirmed` is used only when the package gate validates.

## Drill

1. Choose questions for one stated target: accuracy, speed, coverage, stability, or a recurring error.
2. Deliver the appropriate HTML, chat, or Markdown format and preserve timing, hints, and raw answers.
3. Finalize records, review errors, update only measured readiness metrics, and schedule the next discriminating attempt.

Completion criterion: every attempted question has a record, feedback, and next action; readiness changes cite those records.

## Review

1. Compare the raw answer with the answer key or rubric and record observable issues.
2. Offer plausible causes, obtain user confirmation when possible, and update `error-log.md` by action value.
3. Choose a redo or variant that can distinguish the leading cause from alternatives.

Completion criterion: observed issue and confirmed cause remain separate, resolved items have later-attempt evidence, and the next check is scheduled.

## Mock

1. Freeze scope, duration, allowed aids, scoring rules, and delivery format before starting.
2. Preserve answers and timing under exam-like conditions; score against source-backed keys or rubrics.
3. Save the mock and review records, then update the report fields listed in `review-and-cram.md`.

Completion criterion: score confidence, time allocation, missed high-yield points, repeated patterns, next drills, and cram additions are recorded.

## Cram

1. Read the current scope, error log, readiness evidence, and remaining time.
2. Select only source-backed or error-backed high-yield facts, methods, traps, formulas, and execution checklists.
3. Export the shortest usable recall artifact and schedule one final retrieval pass.

Completion criterion: every item has a source/error basis, speculative additions are marked, and no broad new learning track was opened.

## Postmortem

1. Preserve actual outcome, timing surprises, source quality, and which preparation signals were predictive.
2. Separate reusable methods from exam-specific content and archive the completed package.
3. Create a new provisional package if the user wants preparation for another exam.

Completion criterion: the package is archived, pre-exam readiness remains unchanged, and reusable lessons are recorded without rewriting historical attempts.
